# YaChanger 0.6

I Wanna Maker 的 Windows 坐标与跳跃求解工具：只读显示玩家精确 X、Y 和 **ya**（Y 的小数部分），从记录的普通静止地面起点搜索原地调整方案。

## 启动与基本操作

解压 `YaChanger-v0.6.0-win64.zip`，双击 `YaChanger.exe`。保留旁边的 `_internal` 文件夹；便携版无需安装 Python。发布与更新位于 [YaChanger Releases](https://github.com/frredomerror91-netizen/YaChanger/releases)。

1. 打开游戏进入关卡，在普通静止方块地面站稳，松开跳跃和方向键。
2. 点击“记录当前坐标”。移动、重生或换房后重新记录。
3. 输入目标 ya，点击“开始分析”。启动时目标留空，也可以使用“用当前 ya”、末位加减和历史目标。
4. 结果会持续更新。左侧勾选允许使用的帧数，点选备选即可在右侧查看操作和每步完整 Y；分析中也可查看、复制和导出。手动选中的方案会保留，后续结果不会把它顶掉。
5. 按步骤执行，落地站稳后使用“核对落地值”。结果区会区分模拟与实测证据。
6. 点击“停止”结束分析并保留结果。**没有总游戏帧数、分析秒数或落地轮数上限**。保留数量只是列表容量，默认500，不会导致搜索结束。

坐标来自只读内存采样。工具不发送按键、不修改游戏内存、配置或存档。游戏失焦可能暂停，可保持工具置顶并把焦点切回游戏。没有游戏时可以使用“离线示例”或“多键示例”；后者一键选好1+2条件，示例起点会明确标注。演示改变的条件可用“恢复默认”还原。

## 重点：多键、多次取消跳跃

启用“普通 + 多键”或“仅多键”，并设置你能同时使用的映射键数量（2–4）。这些键需要由你使用的改键软件各自映射为跳跃。工具不会替你改键。

一次起跳中先同时按住多个跳跃键，再依次松开。上升期间的每次独立松键都按多键事件模型再次执行 `ySpeed *= jumpReleaseFactor`，随后继续该帧的重力、移动和碰撞。第二次松键是 **release-only**，不能当作重新按跳，也不能用会同时产生按下沿的瞬时跳来冒充，否则会误用二段跳。

- `2f+2（2键）`：首次取消按本工具的 jtool 口径计为2f，再过2帧释放第二个键。
- 参考软件默认 **0f** 口径的 `1+2` 对应上述方案：先保持1个内核采样帧，下一帧松开A，再隔2帧松开B。若参考软件选1f口径，第一段数值会多1；本工具在步骤旁同时列出参考0f记法。
- `+` 后的数值是两次松键事件的间隔，不是新的一跳。主界面的帧数勾选约束每次起跳到**第一次取消**的帧数；追加间隔由“追加松键间隔”设置控制。
- A/B/C/D 指你改键后各自映射为跳跃的键，不是要求按字母键。
- “最多映射键”包括2至所设数量的方案；每次取消都单列操作与取消后的完整 Y。支持一段跳、多键二段跳及跨多次落地的组合。
- 多键同时按下仍计为一次游戏起跳；“需要几个映射键”单独显示。二段跳的70%规则比较游戏起跳次数。

默认物理下，从 `Y=309.399993896484375` 执行参考0f记法 `1+2`，模型预测如下：

| 核对时机 | 正确完整 Y |
| --- | --- |
| 保持1帧后，第一次松开前 | 301.29998779296875 |
| 松开A，第1次取消后 | 298.05499267578125 |
| 再过2帧松开B，第2次取消后 | 294.329742431640625 |
| 落地站稳 | 309.327239990234375 |

多键部分已通过独立速度公式、标量重放、批量模拟和界面联动核验；**尚未将真实改键软件的多键操作标为游戏实测通过**。实际是否产生独立松键事件取决于改键方式，请按步骤中的 Y 核对。

## 常驻筛选与便捷选项

- 帧数直接勾选：勾选允许、取消排除；提供全选、全不选、反选和2–6f短跳预设。全部取消时会提示先选择帧数。
- 普通＋多键 / 仅普通 / 仅多键；最多映射键数、追加松键间隔、是否比较二段跳、二段跳是否允许多键。
- 自动/自定误差及偏大、偏小、两侧方向；完整 Y 模式在侧栏选择。
- 流畅、均衡、全速三种运行模式，调整批次大小；同等条件优先简单操作可关闭。
- 列表容量、二段跳首选节省比例、记住筛选设置、恢复默认。
- 用当前 ya 作为目标、按最后一位单位加减、最近8个目标。目标最多24位小数；末尾0保留精度意义。
- 快捷键：F6记录、F7分析/停止、F8复制方案、Esc停止；仅工具窗口获得焦点时生效。

较长的侧栏和操作步骤均可滚动。设置保存在便携目录 `preferences.json`；关闭“下次保留这些设置”可停用。历史目标不会自动填入启动时的目标框。

## 误差与排序

ya 使用 `y-floor(y)`。默认最大绝对误差为目标最后一位的小数单位：`0.43` 对应 `±0.01`，`0.3912` 对应 `±0.0001`，`0.4300` 对应 `±0.0001`。自定误差为0表示零误差；方向包括等号；误差不跨0/1循环。

综合推荐兼顾误差与跳数，优先一段跳；二段跳默认须比符合条件的一段跳最少跳数方案减少至少70%，才进入综合首选比较。没有一段跳解时可推荐二段跳。精度优先与少跳优先按所选指标排序。同等条件可优先更简单的按键操作。推荐是当前已探索候选中的结果，不是所有可能输入的全局最优证明。

普通短跳按 [jtool 的计数方式](https://github.com/patrickgh3/jtool/blob/master/source.gmx/scripts/jumpDurations_EndStep.gml) 显示，包含松键减速帧；例如 jtool 4f 对应按住3个内核采样帧后松开。满跳单独显示。“1f瞬时跳”需要同一帧按下并松开。每次一段跳之间默认先落地，普通方案省略松开等待帧数。

## 算法与适用范围

0.6合并了未单独发布的0.5改版：按完整原生状态复用落地转移，保留不同输入路径；用批量原生计算及反向距离引导的惰性路径搜索整理备选。多键搜索只在还能影响上升速度的事件时机继续分支；已经落地、不能再触发二段跳的分支提前结束。仅多键模式的反向估计同时记录是否已使用多键，避免精度排序被普通解循环拖住。更改目标可复用相同记录场景的兼容转移缓存。

位置逐帧按 float32 存回，速度保留 double 原始位；碰撞继续使用提供的原生内核。参考旧求解器的事件分支与记法，不套用它的GM8、1×1 Dotkid碰撞结果。原始iwbot源码与DLL不修改。

支持普通静止方块地面的原地调整。水、藤蔓、薄板、传送门、动态危险物或不支持的局部物体会说明原因并拒绝分析。真实游戏状态、按键事件与模型预测需分别核对；稳定落地吻合也不能唯一证明整条按键时机完全正确。

同一起点 `309.399993896484375`、目标 `.299957275` 的普通跳跃两秒观察基准，0.6已达到500个保留解，并保留4f→3f；性能数据和版本对比在本地开发验证记录中，具体耗时随机器、帧数筛选及场景变化。

## 更新、导出与诊断

启动后后台检查 [GitHub稳定版](https://github.com/frredomerror91-netizen/YaChanger/releases)。有新版时点击版本按钮打开下载页；联网失败不影响读取和求解。没有静默安装或后台游戏输入功能。

JSON导出使用 `yachanger-recipe/2`，输入编码 `held-release-press/v2`：bit0为保持按住，bit1为独立松键，bit2用于同帧按下/松开事件。包含所需映射键数、参考记法、逐步核对 Y、所选方案和备选。旧版仅将0/1视为按住的解析器不能正确执行这种事件序列。

源码启动：64位Python3.12+（带tkinter），安装 `requirements.txt`，运行 `python -m yachanger`，保留必需的iwbot运行文件。

```powershell
python -X utf8 -m yachanger --probe --out artifacts/live_probe.json
python -X utf8 -m yachanger --self-test --out artifacts/selftest.json
python -X utf8 -m yachanger --demo-solve 0.3500 --sort fewest
python -X utf8 -m unittest discover -s tests -q
python -X utf8 tools/ui_smoke.py
```

控制台求解同样持续运行，按Ctrl+C停止并输出已找到的结果。错误日志在 `logs/app.log`。

构建入口：`python -X utf8 tools/release.py`；构建依赖用 `python -m pip install --target .build-deps pyinstaller==6.22.3` 安装。后续更新按项目授权使用 `--publish`，先测试、构建、从冻结包验证，再核验账号及远端资产摘要；中断后用 `--publish --reuse-build` 保持同一资产重试。v0.4.0仍强制禁止发布。发布包只包含工具、必需依赖、说明和校验，不包含游戏、凭据、用户设置或研究资料。
