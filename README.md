# Itool 1.0

Itool（原 YaChanger）用于只读查看精确坐标和搜索 ya 跳跃方案。启动游戏后点顶部 **选择进程…**，按程序名或 PID 筛选，选中实例再连接。默认 `auto` 自动识别受支持的 IWM、GMS1 VM 与已校准的 GM8.1；也保留 `iwm`、`gms`、`gm8` 手动内核，选择与实际引擎不符时会说明原因。进程退出、PID复用后需重新选择。

本次新增 tuhkakuppi ver5.2 的 **GM8 与 GMS 两个程序**，原创 I + 跳跃轨迹图标、浅色/深色/跟随系统主题、主题记忆和页签/选项状态动画。GM8坐标与速度保留float64，GMS使用float32；完整Y匹配会自动选择对应精度。

求解范围为正重力普通角色、静态矩形地面与上方无障碍的原地跳跃，方块使用Collision时机（`stepBlock=0`）；GMS使用矩形遮罩（`preciseMask=0`）。物理模式读取当前游戏值。未校准构建、其他碰撞时机、水、藤蔓、平台、天花板、危险物、Dotkid或特殊变换会明确说明限制；不能作为求解起点时仍保留已记录坐标。模型重放通过不代表所有改键硬件组合均已实测。

解压 **Itool-v1.0.0-win64.zip** 后启动 **Itool.exe**，英文入口为 **Itool-English.cmd**，请保留旁边的`_internal`。记录起点（暂停时也可）、输入目标ya后开始分析。默认找到100个解自动停止，0表示手动停止。排序即时生效；筛选和误差改变搜索条件。步骤只显示每次稳定落地后的完整Y；连续一段跳默认先落地，多次取消统一为`1+3`等记法。

用户已明确恢复v1.0发布，现有仓库仍为私密，名称与可见性不变。公开更新接口不能认证访问私密仓库，下载需登录[仓库Release](https://github.com/frredomerror91-netizen/YaChanger/releases)，程序不携带Token。

## 使用细节

- 首选常规且少跳的方案；二段跳默认需减少至少70%的跳跃才优先。可切换精度/少跳排序、组合优先序及首跳/二段独立帧数筛选。
- 目标留空启动；一段跳1–23f、二段跳1–19f。默认误差为目标最后一位的单位，可自行设置绝对误差及偏大/偏小方向。
- 列表默认保留500个方案；取消自动停止后，500解后以低占用继续搜索。可以停止并立即重新分析。
- F6记录、F7开始/停止、F8复制，仅工具聚焦时生效。操作步骤只展示落地Y，轨迹和详细输入保留真实空中值。
- JSON沿用yachanger-recipe/2与held-release-press/v2，增加numeric_model区分数值内核。
- 默认1180×780、最低1060×700。系统主题在启动或重新选择时读取；动画可在设置关闭，并尊重系统减少动态偏好。
- 源码运行python -m yachanger，保留此兼容模块名。构建入口python -X utf8 tools/release.py；发布使用--publish，已验证包可加--reuse-build。包内不含游戏或凭据。

## 物理与验证范围

引擎接入只读内存，不自动操作游戏，不修改原始iwbot或游戏。校准基于用户提供的tuhkakuppi5.2构建、附带Technical说明及实际坐标读取；其他GM8构建需另外校准。GMS脚本和遮罩也需匹配。普通地面外的机制不保证支持。

93项单元测试、中英小窗口检查、两个真实游戏进程的坐标记录及普通/二段/多取消模型重放已通过。新引擎所有跳法尚未逐项用真实硬件按键实测。
