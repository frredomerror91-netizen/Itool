# YaChanger 0.8

I Wanna Maker 的 Windows 坐标与跳跃求解工具：只读显示玩家精确 X、Y 和 **ya**（Y 的小数部分），从记录的普通静止地面起点搜索原地调整方案。

## 启动与基本操作

解压 `YaChanger-v0.8.0-win64.zip`，双击 `YaChanger.exe`。保留旁边的 `_internal` 文件夹；便携版无需安装 Python。发布与更新位于 [YaChanger Releases](https://github.com/frredomerror91-netizen/YaChanger/releases)。

1. 打开游戏进入关卡，在普通静止方块地面站稳，松开跳跃和方向键。
2. 点击“记录当前坐标”。移动、重生或换房后重新记录。
3. 输入目标 ya，点击“开始分析”。启动时目标留空，也可以使用“用当前 ya”、末位加减和历史目标。
4. 结果会持续更新。左侧勾选允许使用的帧数，点选备选即可在右侧查看操作和每次落地后的完整 Y；分析中也可查看、复制和导出。手动选中的方案会保留，后续结果不会把它顶掉。
5. 按步骤执行，落地站稳后使用“核对落地值”。结果区会区分模拟与实测证据。
6. 默认找到100个不同输入方案后自动停止并保留结果；侧栏“自动停止解数”可修改，填0改为手动停止。也可随时点击“停止”。**没有总游戏帧数、分析秒数或落地轮数上限**。保留数量只是列表容量，默认500，本身不会结束搜索。只有自动停止数量设为0或大于500时，才会继续进入500解降速阶段：默认找到500个匹配后自动切到约15%工作占空比，慢慢继续搜索；侧栏可调整触发数量以及5%/15%/30%后台模式。这是计算/休息比例，实际CPU占用随机器和单个批次耗时变化。

未连接游戏时，“当前ya”显示默认值`0.399993896484375`，完整X/Y仍为“—”，不会伪造游戏样本或记录起点。连接后替换为实时值。

坐标来自只读内存采样。工具不发送按键、不修改游戏内存、配置或存档。游戏失焦可能暂停，可保持工具置顶并把焦点切回游戏。没有游戏时可以使用“离线示例”或“多键示例”；后者一键选好2+2条件，示例起点会明确标注。演示改变的条件可用“恢复默认”还原。

## 重点：多键、多次取消跳跃

启用“普通 + 多键”或“仅多键”，并设置你能同时使用的映射键数量（2–4）。这些键需要由你使用的改键软件各自映射为跳跃。工具不会替你改键。

一次起跳中先同时按住多个跳跃键，再依次松开。左侧筛选、优先列表、右侧步骤和复制内容统一采用 `X+N`，首次数字使用jtool计数，组合中不再加f后缀。上升期间的每次独立松键都按多键事件模型再次执行 `ySpeed *= jumpReleaseFactor`，随后继续该帧的重力、移动和碰撞。第二次松键是 **release-only**，不能当作重新按跳，也不能用会同时产生按下沿的瞬时跳来冒充，否则会误用二段跳。

- `2+2`：首次取消按jtool口径计为2f，再过2帧释放第二个键。
- `1+4`：同帧起跳并首次松键，再隔4帧松开第二个键；旧侧栏0f记法曾显示为`0+4`。现在左右都显示`1+4`。
- 旧版本偏好中的0f组合会自动把首数字加1，例如旧`0+4`→`1+4`、旧`4+4`→`5+4`，保持对应的原始输入事件不变。新选择`4+4`则左右均为`4+4`。
- `+` 后的数值是松键事件间隔，不是新的一跳。主界面帧数勾选约束该类别的首次取消计数；追加间隔另设。
- A/B/C/D 指你改键后各自映射为跳跃的键，不是要求按字母键。
- “最多映射键”包括2至所设数量的方案；每次跳跃只列一条组合；操作步骤只在落地站稳时显示完整 Y，空中 Y 在“跳跃轨迹”和“详细输入”查看。支持一段跳、多键二段跳及跨多次落地的组合。
- 多键同时按下仍计为一次游戏起跳；“需要几个映射键”单独显示。二段跳的70%规则比较游戏起跳次数。

默认物理下，从 `Y=309.399993896484375` 执行统一记法 `2+2`（旧参考0f记法`1+2`），模型预测如下（空中数值只用于说明物理，不在操作步骤中展示）：

| 核对时机 | 正确完整 Y |
| --- | --- |
| 保持1帧后，第一次松开前 | 301.29998779296875 |
| 松开A，第1次取消后 | 298.05499267578125 |
| 再过2帧松开B，第2次取消后 | 294.329742431640625 |
| 落地站稳 | 309.327239990234375 |

多键部分已通过独立速度公式、标量重放、批量模拟和界面联动核验；**尚未将真实改键软件的多键操作标为游戏实测通过**。实际是否产生独立松键事件取决于改键方式，请按每次落地后的完整 Y 核对。空中上升时真实 Y 整数部分也会变化，不把它改成虚假的落地整数。

## 常驻筛选与便捷选项

- 一段跳只列1–23f与满跳；空中二段只列1–19f与满跳。两类分别勾选、互不影响。帧数直接勾选：勾选允许、取消排除；提供全选、全不选、反选和2–6f短跳预设。全部取消时会提示先选择帧数。
- 普通＋多键 / 仅普通 / 仅多键；最多映射键数、追加松键间隔、是否比较二段跳、二段跳是否允许多键。
- 自动/自定误差及偏大、偏小、两侧方向；完整 Y 模式在侧栏选择。
- 流畅、均衡、全速三种运行模式，调整批次大小；同等条件优先简单操作可关闭。
- 默认100解自动停止（0为手动），列表容量默认500、500解后后台降速是两个独立规则；还可设置二段跳节省比例、偏好记忆与恢复默认。
- 默认推荐常规跳在前，同类优先少跳；多次取消同跳数时，首次保持较短的1+2/1+3优先于16+2。可切换多次取消优先、综合误差/跳数，以及首次取消短/映射键少/精度优先。
- 指定多次取消统一使用界面计数：从下拉选首次取消帧数及后续间隔，点击“优先靠前”“仅允许”或“排除”。例如选择4+4，方案同样显示4+4；再次加入优先列表会移到最前，按列表先后排序。“仅允许”要求每个多次取消跳跃都在列表中，普通跳仍可使用。
- 选中项整个按钮填色，不使用x或勾；按钮悬停、按下及选择状态有约120毫秒颜色过渡，不阻塞操作。“轻量交互动画”可关闭，并遵从Windows客户端区域动画偏好。
- 默认窗口1180×780，最低1060×700，缩小顶部卡片、边距和按钮空隙；落地Y完整显示，长设置及步骤独立滚动。
- 中英文在顶部即时切换，也可运行`YaChanger-English.cmd`或`YaChanger.exe --lang en`。英文使用说明见[README.en.md](README.en.md)。
- 用当前 ya 作为目标、按最后一位单位加减、最近8个目标。目标最多24位小数；末尾0保留精度意义。
- 快捷键：F6记录、F7分析/停止、F8复制方案、Esc停止；仅工具窗口获得焦点时生效。

较长的侧栏和操作步骤均可滚动；超过24张操作卡片时分页显示，使用底部‹/›翻页。较长轨迹会在后台核对，可继续查看其他方案或开始新分析。设置保存在便携目录 `preferences.json`；关闭“下次保留这些设置”可停用。历史目标不会自动填入启动时的目标框。

## 误差与排序

默认绝对误差取输入末位单位：0.43对应±0.01，0.3912对应±0.0001；末尾0保留精度意义。可自定误差并选择只偏大、只偏小或两侧都允许。误差比较不在0和1之间循环取近路。

顶部排序立即重排已经找到的方案，无需重新分析：

- 综合推荐：默认常规跳优先，同类优先少跳；多次取消同跳数时首次保持短优先。侧栏可改为综合误差/跳数、特殊跳优先或自定义组合优先。
- 优先精度：先比较最终ya与目标误差，再比较跳数。
- 优先少跳：先比较起跳次数，再比较误差。

指定组合优先和多次取消顺序用于“综合推荐”，精度/少跳模式遵从明确选择的首要指标。帧数或误差等可行性规则变更会取消旧分析，需要重新开始；排序、优先列表和操作简单程度只改变当前显示顺序。手动点选的方案保留在步骤区，列表推荐与当前检查的方案可能不同。二段跳默认需比已知最少地面跳解减少至少70%起跳，才进入综合首选组。

## 算法与适用范围

0.6合并了未单独发布的0.5改版：按完整原生状态复用落地转移，保留不同输入路径；用批量原生计算及反向距离引导的惰性路径搜索整理备选。多键搜索只在还能影响上升速度的事件时机继续分支；已经落地、不能再触发二段跳的分支提前结束。仅多键模式的反向估计同时记录是否已使用多键，避免精度排序被普通解循环拖住。同一次搜索内复用兼容转移缓存。0.7每次分析使用独立低优先级进程，停止后回收该进程的图、路径和缓存，避免旧任务阻塞新任务。停止立即保留已经显示的结果，不等待旧搜索完成最后一次全量排序。A*工作队列使用内存预算，队列过大时保留估计成本较低的路径继续搜索；不承诺穷举所有组合或证明无解，也没有新增总帧数/轮数/时间限制。

位置逐帧按 float32 存回，速度保留 double 原始位；碰撞继续使用提供的原生内核。参考旧求解器的事件分支与记法，不套用它的GM8、1×1 Dotkid碰撞结果。原始iwbot源码与DLL不修改。

支持普通静止方块地面的原地调整。水、藤蔓、薄板、传送门、动态危险物或不支持的局部物体会说明原因并拒绝分析。真实游戏状态、按键事件与模型预测需分别核对；稳定落地吻合也不能唯一证明整条按键时机完全正确。

同一起点 `309.399993896484375`、目标 `.299957275` 的普通跳跃两秒观察基准，0.6已达到500个保留解，并保留4f→3f；性能数据和版本对比在本地开发验证记录中，具体耗时随机器、帧数筛选及场景变化。

## 更新、导出与诊断

启动后后台检查 [GitHub稳定版](https://github.com/frredomerror91-netizen/YaChanger/releases)。有新版时点击版本按钮打开下载页；联网失败不影响读取和求解。没有静默安装或后台游戏输入功能。

操作步骤和复制内容只显示落地检查点；JSON保留真实完整轨迹及空中事件，并用`show_coordinate`标记步骤是否展示坐标。英文界面导出的操作说明使用英文，物理事件与数字不变。

JSON导出使用 `yachanger-recipe/2`，输入编码 `held-release-press/v2`：bit0为保持按住，bit1为独立松键，bit2用于同帧按下/松开事件。包含所需映射键数、统一记法`jtool-multi/v1`、停止原因、逐步核对Y、所选方案和备选。旧0f记法只保留在兼容元数据中，原始事件检查点保存在`event_rows`；玩家步骤按每次跳跃简写，不重复列出每次松键。旧版仅将0/1视为按住的解析器不能正确执行这种事件序列。

源码启动：64位Python3.12+（带tkinter），安装 `requirements.txt`，运行 `python -m yachanger`，保留必需的iwbot运行文件。

```powershell
python -X utf8 -m yachanger --probe --out artifacts/live_probe.json
python -X utf8 -m yachanger --self-test --out artifacts/selftest.json
python -X utf8 -m yachanger --demo-solve 0.3500 --sort fewest
python -X utf8 -m unittest discover -s tests -q
python -X utf8 tools/ui_smoke.py
```

控制台默认同样100解自动停止；可用`--stop-after 0`持续求解，或设置其他数量。Ctrl+C随时停止并输出已找到结果。错误日志在 `logs/app.log`。

构建入口：`python -X utf8 tools/release.py`；构建依赖用 `python -m pip install --target .build-deps pyinstaller==6.22.3` 安装。后续更新按项目授权使用 `--publish`，先测试、构建、从冻结包验证，再核验账号及远端资产摘要；中断后用 `--publish --reuse-build` 保持同一资产重试。v0.4.0仍强制禁止发布。发布包只包含工具、必需依赖、说明和校验，不包含游戏、凭据、用户设置或研究资料。
